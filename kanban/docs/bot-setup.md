# Подключение бота Max Канбан к чату

Пошаговая инструкция: от панели MAX до рабочей связки «чат ↔ доска».
Тот же сценарий короче изложен в мини-приложении: кнопка «?» в шапке →
«Подключение чата».

## 1. Настройки на платформе MAX для партнёров

business.max.ru → **Чат-боты** → `⋮` → **Настройки**:

1. **Токен** — скопируйте в `.env` как `MAX_BOT_TOKEN`.
2. **Приватность** — разрешите добавление бота в групповые чаты
   (по умолчанию запрещено, без этого бота нельзя добавить в чат).
3. **Мини-приложение** — вставьте URL строго как `FRONTEND_URL`
   (например `https://kirillgvoz.ru/max-kanban/`), выберите кнопку
   и нажмите **Сохранить**. Без этого диплинки на доску/задачу
   не откроют приложение (сами сообщения бота доходят всегда).

## 2. Переменные окружения

```env
MAX_BOT_TOKEN=<токен из панели>
MAX_BOT_NAME=se14445725_bot
FRONTEND_URL=https://kirillgvoz.ru/max-kanban/
MAX_WEBHOOK_URL=https://kirillgvoz.ru/max-kanban/webhook
WEBHOOK_SECRET=<длинный случайный секрет>
```

Подписка вебхука (`message_created,message_callback,bot_started,bot_added`)
создаётся backend'ом автоматически при старте.

## 3. Добавление в чат — обязательно администратором

1. В MAX добавьте бота в рабочий чат как участника.
2. **Назначьте бота администратором чата.** Без этого бот не видит
   сообщения (команды не доходят) и не может закреплять доску
   и управлять ею. Это самая частая причина «бот молчит».
3. Отправьте в чат `/start` — бот должен ответить приветствием.

## 4. Привязка доски

В чате (участник с ролью owner/admin организации):

```
/link board_<id>
```

ID доски — в мини-приложении: доска → шестерёнка → вкладка «Чаты».
После привязки бот **закрепит сообщение доски** в чате.
Дальше из чата работают:

- `/new Название задачи` — создать задачу;
- `/tasks` — доски чата и ближайшие дедлайны;
- кнопки **«Взять» / «Готово»** под уведомлениями — двигают задачу
  по статусам (нажимать может только участник организации).

Отвязка: `/unlink board_<id>` — бот снимет своё закреплённое сообщение
(чужой закреп не трогает).

## 5. Диагностика

- Таблица `webhook_events` — каждое доставленное событие MAX.
  Нет строки — сообщение не дошло до backend'а (бот не админ,
  нет подписки, недоступен вебхук).
- `docker compose logs backend`:
  - `open_app button rejected … retrying` — URL мини-приложения
    в панели не совпадает с `FRONTEND_URL`, ответы уходят текстом;
  - `pin … failed` — боту не хватает прав администратора;
  - `invalid bot start update` — событие без chat_id, смотреть payload.
- `notification_outbox` — очередь уведомлений (`pending/sent/failed`,
  `last_error` с причиной).
